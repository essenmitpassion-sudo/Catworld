### Vorbereiteter Installationsweg für Werkzeugrechner

Diese Schritte sind eine Bauanleitung, keine Behauptung lokal bereits gelieferter Binärdateien. Voraussetzungen und vollständige Plattformmatrix: [PLATFORMS.md](PLATFORMS.md). Aktiven UDI-Branch verwenden; nach frischem Checkout zuerst `npm ci`, `npm run native:prepare` und `npm run native:check`. Die App bleibt ohne freigegebenen Dienst ausdrücklich unverbunden.

- **Android:** Mit JDK21 und Android-SDK36 im Ordner `android/` `./gradlew assembleDebug` bzw. `gradlew.bat assembleDebug`. Erwartete erzeugte Datei: `android/app/build/outputs/apk/debug/app-debug.apk`. Auf genau dem bewusst ausgewählten Testgerät/Emulator mit `adb -s <Gerätekennung> install -r <APK-Datei>` installieren; danach UDI starten und Installation/Version/Abläufe im Bogen festhalten. Solange die Datei nicht erzeugt und installiert wurde, keine Paketabnahme eintragen.
- **iOS-Simulator:** Auf einem passenden Mac (aktuelle CI: Xcode26.6) das vorhandene Projekt bauen: `xcodebuild -project ios/App/App.xcodeproj -scheme App -configuration Debug -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' -derivedDataPath artifacts/ios-simulator CODE_SIGNING_ALLOWED=NO build`. Erwartete App: `artifacts/ios-simulator/Build/Products/Debug-iphonesimulator/App.app`. Für die integrierte Bedienprüfung in Xcode App-Scheme und einen verfügbaren iPhone-Simulator wählen, dann Product → Test. Alternativ `xcodebuild test -project ios/App/App.xcodeproj -scheme App -destination 'platform=iOS Simulator,id=<bewusst gewählte Kennung>' -parallel-testing-enabled NO CODE_SIGNING_ALLOWED=NO`; Xcode installiert die Ziel-App selbst. Der neue integrierte Testweg benötigt noch seine praktische CI-Abnahme. Diese unsignierte Simulator-App ist kein IPA für ein iPhone; Apple-Signierzugang und physisches Testgerät fehlen weiterhin.

## P2 · hilfreiche Weitergabe statt QR-Zwang

Primär eine Suche mit ihren Kriterien teilen, keine Preis-/Bestandsmomentaufnahme als aktuelle Wahrheit. Der Empfänger sieht eine bearbeitbare Zusammenfassung und startet selbst eine neue Prüfung. Links dürfen keine Sprachaufnahme, Schlüssel oder Zugangstoken enthalten. Suchtext kann persönlich sein; vor Freigabe sichtbar machen und bewusst bestätigen. Ein QR-Code ist später lediglich ein zusätzlicher Transport desselben Links, etwa auf einem zweiten Bildschirm. Auf einem einzelnen Telefon schafft ein QR-only-Einstieg zusätzliche Reibung.

Im Projekt umgesetzt: «Diese Suche teilen» → Link zur Prüfung vorbereiten → bewusst kopieren oder bei geeigneter Adresse das native Teilen nutzen. Die Suchabsicht liegt im URL-Fragment, wird nicht als Query an den Server geschickt und enthält keine Angebotsdaten. Änderungen machen die vorbereitete Vorschau ungültig. Beim Empfang wird eine ältere Suche abgebrochen; es erscheinen Wunsch und Kriterien, keine automatisch angefragten Angebote. Lokale Links werden ausdrücklich als Testlinks für denselben Computer bezeichnet. Es gibt noch keinen allgemein verwendbaren UDI-Host und keinen eingebauten QR-Generator.

Es gibt keinen belegten plattformübergreifenden Deferred-Deep-Link-Dienst. Die App verspricht nicht, den Inhalt nach einer Neuinstallation automatisch wiederherzustellen. Sicherer Rückfall: Original-Link behalten und nach Installation erneut öffnen. Ohne freigegebene mobile Adresse keine allgemein nutzbaren Freigabelinks erzeugen; lokale Links als solche erklären. Keine Empfehlungscodes, Prämien, Kontaktbuchimporte oder Kampagnenmechanik im ersten Pilot.
